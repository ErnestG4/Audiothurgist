### B. Hardening borrowed from Kyklophoria (cheap, each under an hour)

1. **Cap the frame accumulator** in `web/hostlink.js` (unbounded today; 4 MB
   of undelimited input killed a tab next door).
2. **Connect-twice fix**: send a lone zero on `Link.start`, raise DTR, retry
   HELLO; a generation counter so two connects in flight don't tear each
   other down.
3. **`static_assert(std::is_trivially_default_constructible<T>)`** at every
   `ALCHEMY_SDRAM_BSS` declaration (a default member initialiser there is a
   hard fault at boot; Kyklophoria bricked a build this way). Audited today:
   clean, but unguarded.
4. **Git-hash build stamp** in the version string (`-dirty` included) so a
   flashed binary can identify itself from the page.
5. **`host.Pages(...)`** so knob metadata reaches the descriptor (cap 8
   pages, ~7.6 KB SRAM — check headroom first: SRAM is at 83 %).
6. **NaN-draw watch** in the web self-test's DOM stub (a canvas draws
   nothing at NaN and nobody notices).
7. **`docs/sdk-quirks.md`** as a standing register (symptom / cause /
   evidence / what to do / upstream ask), seeded from the GetUs note, the
   boost patch, the silent over-large-reply drop, `Pager::SetStored`'s null
   deref, the bitwise `Crc32`, and the `Pump()`-before-poll extra millisecond.

### C. Infrastructure with real payoff (each a day or two)

8. **A shared StateExt header** compiled into the firmware and a **desktop
   `--serve` shell** speaking HostLink on stdio, with `--card <dir>` — so the
   page's sound-changing paths are graded against the real engine, not
   `demo.js`. Kyklophoria's worst bug hid in exactly this gap (its fake
   applied nothing), and Audiothurgist's `demo.js` has already diverged from
   the firmware once (`clearKey`). Keep `demo.js` for the no-binary demo.
9. **`make armcost`** — Cortex-M7 instruction counts for the engine's inner
   loops (zoom read, fades, looper fire, `ApplyEdit`, the Adaptive lens).
   Every CPU claim here is a desktop reading; Kyklophoria's wavefolder was
   2.7 µs on x86 and 150 µs on the M7.
10. **Rendered-audio goldens** driven by a tiny script (Kyklophoria has 21
    WAVs at 1e-6); Audiothurgist pins a grammar hash and engine sums, not
    audio.
11. **Paged, count-first, stop-before-overflow replies** for `GET_TABLE`,
    `GET_HITS`, sets lists; note the SDK's silent drop of over-large replies.
12. **Nibble-table CRC32** (0.6 ms inside a 1 ms poll on a 7.5 KB blob);
    an upstream candidate too.
13. **Review process**: the next review pass is by *paradigm* — a player's
    ears, instrument ergonomics, audio-thread numerics, protocol,
    representation — each reviewer writes its own file, then a second round
    where every reviewer reads the others' and withdraws or disagrees. Claims
    labelled measured / reasoned / hunch. Not "verify before reporting".

## 3. Priorities, recommended order

1. **Hardening B1–B4 now** (a couple of hours, no behaviour change): they
   make every hardware session that follows more honest — a binary that
   names its hash, a link that connects first time, a page that can't be
   killed by a burst.
2. **One consolidated hardware pass, 45 minutes**, ordered so each step
   proves the ground under the next: boot + version → clock (×2 holds two
   minutes) → sampling into keys → Kit editor drag with audition → panel
   Edit page → autosave and reload → scope gates preset → Adaptive A/B.
   Written as `docs/hardware-pass-2026-09.md` with a "listen for" per step,
   replacing the four overlapping checklists.
3. **Fix what the pass finds.** Expect the panel Edit page and the touch
   gestures to need the most.
4. **C8 the desktop shell + shared StateExt**, before any further page
   features, so the fake-vs-firmware gap closes.
5. **Alpha-2**, then the playing-and-visualizing phase (F).

Everything in C9–C13 and D is queued behind the pass; none of it blocks
playing.
